# بررسی اجرای staging

تاریخ: ۲۰۲۶-۱۰-۱۵؛ مبنای کد: `9b356daf2`.

## کارهای انجام‌شده

- Docker محلی فعال است؛ درایور VFS، دیسک ۳۲GB، حدود ۶٫۷GB فضای آزاد، RAM حدود ۳۳GB.
- سازندهٔ مستقل BuildKit با snapshotter نوع native و فضای موقت tmpfs با سقف ۱۲GB در RAM راه‌اندازی شد. سلامت سرویس و mount حافظه تأیید شدند. درایور یا daemon اصلی Docker تغییر نکرد.
- خروجی build برای یک آرشیو Docker محلی تنظیم شد تا پس از ساخت، کش RAM آزاد و سپس فقط تصویر نهایی بارگذاری شود. این مسیر هنوز به build موفق نرسیده؛ ظرفیت کافی برای کل build و اجرای همهٔ کانتینرها ادعا نمی‌شود.
- تنظیمات خصوصی staging با کلید مستقل، cookie مستقل، mailer لاگ و نام دیتابیس جدا خارج از Git آماده شد. هیچ credential وارد مخزن نشد.

## مانع مشاهده‌شده

پیش از اجرای مراحل Dockerfile، دریافت metadata تصاویر پایه متوقف شد:

```text
https://registry-1.docker.io/v2/library/node/manifests/24-bookworm-slim
503 Service Unavailable
```

هر دو مسیر BuildKit و `docker pull node:24-bookworm-slim` همین پاسخ را دادند. درخواست تشخیصی به `/v2/` نیز پاسخ ۵۰۳ و خطای اتصال upstream پراکسی با عبارت `remote connection failure` و `Invalid argument` برگرداند. این خطا، رد مجوز صریح یا خطای برنامه نیست. وضعیت runtime محیط running است، اما ابزار وضعیت، اجرای سیاست شبکه را unknown گزارش می‌کند؛ فهرست مقصدهای تعریف‌شده شامل registry-1.docker.io است. بنابراین اضافه‌کردن دوبارهٔ همان دامنه یا درخواست توکن GitHub این مشکل مشاهده‌شده را حل نمی‌کند.

سازندهٔ RAM و تصویر آن پس از تشخیص حذف شدند. دیتابیس خالی متعلق به همین آزمون نیز حذف شد؛ دیتابیس و volume توسعه و کانتینرهای اصلی حفظ شدند. بررسی HTTP/CSS، Reverb و مصرف صف محیط توسعه پس از پاک‌سازی مجدداً موفق بود.

## وضعیت باقی‌مانده

اجرای تصویر نهایی روی staging، آزمون restart و بازگشت همان تصویر هنوز انجام نشده‌اند. پس از رفع اتصال رجیستری از سمت محیط ابری، build و سپس این آزمون‌ها باید ادامه یابند. نتایج موفق فاز ۷، آزمون‌های کد و مرورگر محیط توسعه‌اند و جای این بررسی را نمی‌گیرند. [گزارش فاز ۷](PHASE_7_REPORT.md) و [راهنمای استقرار](RELEASE_GUIDE_FA.md).
