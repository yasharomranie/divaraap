# دیپلوی با دکمهٔ Git Version Control

این روش از دکمهٔ cPanel استفاده می‌کند؛ به کرون یا اجرای شل از درخواست PHP نیاز ندارد. مسیر دامنه همان `adorax/public_html` باقی می‌ماند. مخزن کنترل‌شده در `/home/yas/adorax/source` و نصب موجود در `/home/yas/adorax/divaraap` است.

## استفاده

1. در Git Version Control مخزن `source` را Manage کنید.
2. در Pull or Deploy، Update from Remote را بزنید.
3. پس از موفقیت انتشار GitHub Actions برای همان کامیت، Deploy HEAD Commit را بزنید.
4. خروجی cPanel باید با `Deployment completed` و شناسهٔ کامیت تمام شود.

فایل `.cpanel.yml` اسکریپت مخزن را اجرا می‌کند. این اسکریپت بستهٔ مخصوص همان کامیت را از انتشار `deploy-main` دریافت می‌کند. اگر انتشار هنوز آماده نباشد، دانلود شکست می‌خورد و نسخهٔ فعال عوض نمی‌شود؛ پس از آماده‌شدن انتشار همان Deploy را دوباره بزنید. هیچ توکنی در فرمان یا مخزن قرار نمی‌گیرد؛ این روش برای مخزن و بستهٔ عمومی فعلی تنظیم شده است.

## حفاظت از سایت موجود

بسته شامل vendor و build هماهنگ است. SHA256 و شناسهٔ کامیت پیش از استخراج بررسی می‌شوند. کد در یک پوشهٔ جدید در `divaraap/releases` و ظاهر همان نسخه در `public_html/_releases` قرار می‌گیرد. `.env`، کلید برنامه، storage و آپلودهای اصلی از نصب موجود استفاده می‌شوند؛ داده‌های کپی‌شدهٔ آزمایشی در source مرجع سایت نیستند.

مکانیزم موجود ReleaseRunner ابتدا از دیتابیس پشتیبان می‌گیرد، مهاجرت‌ها و کش‌ها را اجرا می‌کند و سپس اشاره‌گر نسخه را اتمی عوض می‌کند. پشتیبان‌گیری به جدول‌های InnoDB نیاز دارد؛ در صورت MyISAM، پیش از مهاجرت متوقف می‌شود و علت در `divaraap/deployment-job.json` ثبت می‌شود. خطای مرحلهٔ مهاجرت می‌تواند نیازمند بررسی و بازیابی دیتابیس باشد؛ برگشت کد، مهاجرت دیتابیس را برنمی‌گرداند.

در پایان، ورودی عمومی استاندارد نصب موجود به‌صورت اتمی بازگردانده می‌شود تا تغییر دستی قبلی به source باقی نماند. نسخهٔ ورودی پیش از تغییر داخل `divaraap/deployments/<id>-index.php` نگه داشته می‌شود. تنظیم Document Root تغییر نمی‌کند. نیازی به کپی دستی asset، vendor یا index نیست.

PHP CLI از مسیرهای مطلق PHP 8.4 هاست پیدا می‌شود. ابزارهای git و curl باید در محیط cPanel در دسترس باشند. دسترسی SSH کاربر برای اجرای وظیفهٔ cPanel لازم نیست، ولی محدودیت اجرایی خود cPanel می‌تواند مانع اجرای آن شود؛ خطای واقعی در خروجی همان وظیفه دیده می‌شود.

اگر cPanel تغییرات محلی ثبت‌نشده را گزارش کرد، Deploy ممکن نیست. فایل‌ها را کورکورانه حذف یا git reset/clean نکنید؛ خروجی تغییرات باید بررسی شود. مخزن source نباید محل نگهداری دادهٔ اصلی کاربران باشد.
