# فاز ۴ — پنل کاربر و تعاملات فارسی

وضعیت: تکمیل در محیط توسعه. مرحلهٔ بعد فاز ۵، مدیریت و محتوای تکمیلی است.

## خروجی

- ترجمهٔ کامل Panel، Conversation و Favorite اضافه شد؛ Offer، Review، Report و Notification از ترجمه‌های فاز ۳ استفاده می‌کنند. منوها، پاسخ‌های آماده، پیام‌های موفقیت و خطاهای ثبت و ویرایش آگهی و ویدیو فارسی هستند. کلیدها و جایگزین‌های متنی انگلیسی حفظ شده‌اند.
- فرم ثبت آگهی با چهار مرحلهٔ واقعی «عکس، دسته‌بندی، اطلاعات، پیش‌نمایش» هماهنگ شد. محدودیت‌های عنوان و توضیحات با اعتبارسنجی سرور یکسان‌اند؛ تعداد و قالب مجاز عکس از تنظیمات نمایش داده می‌شود. خطاهای آپلود قابل مشاهده و خواندن هستند و مرحلهٔ جاری مشخص است.
- دسته‌های پیش‌فرض و گزینه‌های ویژگی‌ها در فرم فارسی‌اند؛ جست‌وجوی دسته نام فارسی و انگلیسی را می‌پذیرد و شناسهٔ اصلی را حفظ می‌کند. نام کشور در نمایش فارسی است و ذخیره‌سازی نام اصلی را نگه می‌دارد تا فیلتر مکان صحیح بماند.
- اصلاح اجرای ثبت آگهی: slug و مالک تولیدشدهٔ سرور دیگر توسط mass assignment حذف نمی‌شوند؛ آگهی تازه طبق رفتار موردنظر فرم در وضعیت pending ذخیره می‌شود.
- مدل PHP محیط با پشتیبانی WebP ساخته شد تا تبدیل عکس آگهی موفق باشد. راه‌انداز، تصویر Docker تغییرکرده را تشخیص می‌دهد و کانتینر PHP را با mountهای قبلی دوباره ایجاد می‌کند؛ دیتابیس و فایل‌های پروژه حفظ می‌شوند.
- گفتگو با API موجود هماهنگ شد: فیلد message و پاسخ message خوانده می‌شوند. اتصال Echo/Pusher به Reverb و نام واقعی رویداد برقرار است، دریافت پیام به هر دو شرکت‌کننده می‌رسد و شناسهٔ پیام از نمایش تکراری جلوگیری می‌کند. دسترسی کانال خصوصی فقط برای مالک حساب است.
- پیام‌ها و ورودی گفتگو dir=auto دارند. Enter هنگام ترکیب نویسه پیام را زود ارسال نمی‌کند؛ Shift+Enter خط جدید می‌سازد. خطای ارسال فارسی است و متن ارسال‌نشده حفظ می‌شود. دریافت پیام در گفتگوی باز، آن را خوانده‌شده ثبت و نشان پیام خوانده‌نشده را به‌روز می‌کند.
- فرم ویدیو نام صحیح video_file را ارسال می‌کند؛ ویرایش شناسهٔ آگهی را نگه می‌دارد و امکان غیرفعال‌کردن دارد. متن وضعیت و مدت ویدیو فارسی است. آزمون آپلود، ذخیره، ویرایش و حذف موفق است؛ تبدیل واقعی ویدیو با FFmpeg در این فاز آزمون نشده است.
- متن اعلان و محتوای پیشنهاد قیمت جهت خودکار دارند؛ محتوای ذخیره‌شدهٔ کاربران بازنویسی نمی‌شود. خطاهای تشخیص خودکار دسته فارسی‌اند و جزئیات داخلی خطای سرویس به رابط منتقل نمی‌شوند.

## شواهد

| بررسی | نتیجه |
| --- | --- |
| PHPUnit | ۷۸ تست، ۸۸۰ assertion موفق؛ ۱۲ تست جدید برای مسیرهای فارسی و تعاملات |
| ثبت آگهی | آگهی فارسی با عکس واقعی تست، مالک و slug معتبر، مکان اصلی و وضعیت pending ذخیره شد |
| ویرایش | عنوان و توضیحات فارسی ذخیره شدند و خطاهای سرور فارسی بودند |
| گفتگو | ذخیرهٔ متن فارسی، انتشار برای هر دو شرکت‌کننده، خوانده‌شدن و منع کاربر غیرعضو تأیید شد |
| اعلان و علاقه‌مندی | خواندن همهٔ اعلان‌ها و ذخیرهٔ جست‌وجوی فارسی تأیید شد |
| build، TypeScript، lint و Pint | موفق |
| مرورگر با دو حساب موقت | ارسال و دریافت واقعی از Reverb با شناسهٔ پیام جدید؛ حفظ متن و نمایش خطای فارسی در پاسخ خطای کنترل‌شده |
| فرم Livewire در مرورگر | آپلود PNG، انتخاب دستی دسته، پیش‌نمایش مرحلهٔ ۴، انتشار و ویرایش فارسی موفق |
| موبایل و دسکتاپ | عرض‌های ۳۹۰ و ۱۴۴۰px؛ مسیرهای پنل بدون سرریز افقی؛ بازگشت از گفتگو در موبایل موفق |
| smoke محیط | پاسخ HTTP و CSS، تحویل پیام Reverb و مصرف job صف موفق |
| Graphify و UI/UX Pro Max | تحلیل وابستگی‌ها، راهنمای فرم/صفحه‌کلید و بازسازی گراف انجام شد |
