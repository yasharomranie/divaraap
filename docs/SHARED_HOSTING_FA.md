# سازگاری با هاست اشتراکی

این تغییر، زیرساخت سازگاری است؛ نصاب وب و دکمهٔ به‌روزرسانی هنوز ساخته نشده‌اند. نصب واقعی روی حساب cPanel ارائه‌دهندهٔ مشتری نیز هنوز انجام نشده است.

## حداقل امکانات

- PHP **۸٫۴ یا بالاترِ سازگار با وابستگی‌های قفل‌شده**؛ کاهش requirement پروژه به PHP قدیمی انجام نشده است.
- **MySQL 8.0 یا 8.4**؛ نصب تازه، seed و suite روی MySQL **8.0.46 و 8.4.11** واقعی و در حالت strict آزمایش شدند. MySQL پیش‌فرض نصب جدید است. MariaDB 11.4.13 نیز قبلاً آزمایش شده است. MySQL 5.7 و قدیمی‌تر تأیید نشده‌اند.
- افزونه‌های PDO MySQL، mbstring، intl، GD با WebP، fileinfo، zip، bcmath، XML/DOM، ctype، iconv و OpenSSL؛ نیازمندی‌های دقیق کتابخانه‌ها با Composer در مرحلهٔ ساخت بسته بررسی شوند.
- HTTPS، دسترسی نوشتن PHP به storage و bootstrap/cache، حافظه و زمان کافی برای ساخت تصویرهای WebP. سقف PHP upload/post و وب‌سرور باید با سقف فایل محصول هماهنگ شود.
- امکان قرار دادن ریشهٔ document root روی پوشهٔ **public**؛ کد، vendor، .env و storage نباید مستقیم در دسترس وب باشند. اگر هاست چنین چیدمانی را نمی‌پذیرد، باید چیدمان بستهٔ نصبی اختصاصی و امن ساخته و آزمایش شود؛ کپی کل پروژه به public_html مجاز نیست.

نمونهٔ تنظیمات بدون رمز در [.env.shared.example](../.env.shared.example) است. نام کاربر/دیتابیس ممکن است پیشوند حساب سی‌پنل داشته باشد. MAIL_MAILER=log فقط برای آزمایش است؛ برای ارسال ایمیل واقعی SMTP باید تنظیم شود.

## رفتار حالت shared

با HOSTING_PROFILE=shared:

- صف sync است و کارها داخل درخواست PHP انجام می‌شوند؛ worker دائمی لازم نیست. کار سنگین جدید نباید بدون بررسی محدودیت هاست وارد این مسیر شود.
- broadcast خارجی خاموش است. مرورگر کاربر واردشده هر پنج ثانیه و فقط در تب قابل مشاهده، پیام و شمارندهٔ خوانده‌نشده را بررسی می‌کند. WebSocket/Reverb و پورت اختصاصی لازم نیست. دریافت پیام ممکن است چند ثانیه تأخیر داشته باشد.
- endpoint پیام احراز هویت، کنترل عضویت گفتگو، دریافت افزایشی، سقف ۱۰۰ پیام در پاسخ، rate limit و no-store دارد. متن پیام به‌صورت متن در DOM درج می‌شود.
- فقط فایل MP4 واقعی پذیرفته می‌شود و همان فایل بدون تبدیل آمادهٔ پخش می‌شود. FFmpeg، FFprobe و صف ویدیو فراخوانی نمی‌شوند. کدک فایل باید در مرورگر مقصد قابل پخش باشد؛ MP4 بودن ظرف فایل تضمین سازگاری همهٔ کدک‌ها نیست. فشرده‌سازی، استخراج مدت/ابعاد و تبدیل فایل‌های دیگر ارائه نمی‌شود.
- عکس‌ها با GD و WebP پردازش می‌شوند؛ optimizerهای باینری خارجی غیرفعال‌اند.
- حالت demo مبتنی بر schemaهای PostgreSQL خاموش است. این demo با سایت اصلی و دادهٔ محصول فرق دارد.
- رسانهٔ عمومی از مسیر Laravel /media ارائه می‌شود؛ symlink لازم نیست. تنظیمات خصوصی و فایل‌های غیرعمومی نباید به دیسک عمومی منتقل شوند.

این مسیر برای امکانات اصلی فعلی به SSH، Composer/npm روی هاست، WebSocket، daemon صف یا Cron وابسته نیست. اجرای وظایف زمان‌بندی‌شدهٔ جدید در آینده باید جدا طراحی شود. درگاه، SMTP، پیامک و سرویس‌های بیرونی همچنان تنظیمات خودشان را لازم دارند.

## دیتابیس و ارتقا

ایندکس‌های یکتای فعال در PostgreSQL حفظ شده‌اند. در MariaDB/MySQL از ستون محاسبه‌شدهٔ nullable به نام active_record و unique مرکب استفاده می‌شود تا حذف نرم، مقدار قبلی را آزاد کند ولی دو رکورد فعال تکراری پذیرفته نشوند. این ستون متعلق به موتور دیتابیس است و نباید دستی مقداردهی یا در import کپی شود.

اصلاح migrationهای پایه برای نصب تازه است؛ دیتابیس PostgreSQL موجود خودکار به MariaDB منتقل نمی‌شود و پاک نمی‌شود. مهاجرت دادهٔ نصب موجود نیازمند export/import اختصاصی با حفظ شناسه‌ها، ارتباط‌ها، دقت ریال و فایل‌های رسانه است. migrate:fresh روی دادهٔ موجود اجرا نشود.

## نتیجهٔ آزمون این اجرا

- نصب تازهٔ migration و seed روی MariaDB 11.4.13 موفق.
- suite کامل PostgreSQL: ۱۲۶ تست، ۲۰۱۷ assertion موفق.
- suite کامل MariaDB: ۱۲۶ تست، ۲۰۱۷ assertion موفق.
- روی هر یک از MySQL 8.0.46 و 8.4.11: ۱۲۶ تست و ۲۰۱۷ assertion موفق؛ ۷ تست restricted PHP با ۳۳ assertion موفق. [شواهد MySQL](MYSQL_COMPATIBILITY_FA.md).
- هفت تست اختصاصی shared با proc_open/exec/shell_exec/system/passthru/popen/symlink غیرفعال: ۳۳ assertion موفق.
- مرورگر واقعی با همین محدودیت PHP: ثبت‌نام و ذخیرهٔ موبایل، بارگذاری عکس، ثبت آگهی ریالی، دریافت پیام با polling و آپلود MP4 موفق بودند.
- ایراد قدیمی فهرست انتخاب آگهی در صفحهٔ ویدیو اصلاح شد و تعویض فایل MP4 با حذف نسخهٔ قبلی آزمون دارد.
- نصب تازهٔ migration روی PostgreSQL نیز جداگانه بررسی شد.
- ممیزی صفحات عمومی روی پروفایل shared در دو زبان و سه عرض در [گزارش مرورگر](release-checks/shared-public-browser.json) ثبت شده است.

معیار تحویل بعدی، بستهٔ آماده شامل vendor و frontend ساخته‌شده، نصاب فارسی و نصب/به‌روزرسانی آزمایشی بدون ترمینال روی یک هاست واقعی مشخص است. این سند جای آن آزمون را نمی‌گیرد.

خلاصهٔ قابل بررسی: [نتایج آزمون‌ها](release-checks/shared-hosting.json). برای توسعه‌دهنده، تنظیمات PHPUnit مخصوص MariaDB در docs/environment/phpunit-mariadb.xml است؛ DB_PASSWORD باید از فایل خصوصی محیط آزمون تزریق شود. این فایل برای دیتابیس آزمایشی مستقل divaraap_shared_testing است؛ روی دیتابیس مشتری اجرا نشود. نصاب آینده همین نیازمندی‌ها را از داخل وب بررسی خواهد کرد.
